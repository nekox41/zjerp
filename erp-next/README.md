# 新版 ERP 独立运行环境

这是新版 ERP 的独立运行栈，与旧版 RuoYi 应用和旧的 server 数据库完全隔离。它包含 MySQL 8.4、Flyway 最终初始 Schema V1、新版 Spring Boot API、独立 Vue 工作空间入口，以及独立持久化的私有业务附件目录。

## 首次启动

在仓库根目录执行：

```bash
cp erp-next/.env.example erp-next/.env.local
# 编辑 erp-next/.env.local，设置三个唯一强随机密钥
docker compose --env-file erp-next/.env.local -f erp-next/compose.yaml up -d --build
```

访问新版入口：`http://localhost:8089/next.html`。API 默认仅通过本机 8090 端口提供，也可在环境文件中修改端口。

首次打开会要求输入环境变量 ERP_BOOTSTRAP_TOKEN 对应的一次性初始化凭据，创建第一个系统管理员（密码至少 12 位）。管理员建立后初始化接口自动拒绝再次初始化。之后使用管理员账号登录。

## 开发

后端独立 Maven 工程，不加入旧版 reactor：

```bash
mvn -f backend/erp-next/pom.xml verify
```

前端仍使用统一 Vue/Vite 工程：

```bash
cd frontend
npm ci
npm run dev
```

Vite 的 `/next-api` 代理默认指向 `http://localhost:8090`。如需修改，可设置 `VITE_NEXT_DEV_API_TARGET`。

## 安全边界

- 只连接独立数据库 `erp_next`，不读取或修改旧版 `server`。
- MySQL 不发布宿主机端口；只有 API/Web 端口对宿主机映射。
- 数据库密码与初始化凭据必须通过环境变量提供；不要提交真实 .env 文件。
- 密码使用 BCrypt；登录令牌为随机不透明值，数据库只保存 SHA-256 摘要；会话可撤销并有过期时间。
- 后端每个请求验证会话和角色权限；前端隐藏入口不是安全边界。
- 管理员初始化只允许在尚无管理员时执行，且需要独立的一次性部署凭据。

## 技术服务报告与附件

- 技术服务报告支持草稿、提交、审核、退回、批准、签发、归档和修订版。
- 每次内容保存生成不可变版本快照及 SHA-256；签发后不可原位修改，只能创建新修订版。
- 报告审核人不能审核自己编制的当前版本；签发人必须与编制人、审核人分离。
- 附件经 API 上传，支持 PDF/JPG/PNG/TXT/DOCX，DOCX 单文件上限 100 MB（生成与最终稿登记一致），其他上传文件上限 25 MB；服务端检查文件签名并计算 SHA-256。
- 附件保存在独立私有卷 `erp_next_private_files`，不挂载到 Web 静态目录；仅通过鉴权 API 下载。
- 归档时保存报告版本、正文 hash、附件 hash 清单和签发时间。

## 数据持久化

`erp_next_mysql_data` 是新版数据库的独立命名卷；`erp_next_private_files` 是独立私有附件卷。普通停止使用 `docker compose down`，不要随意使用 `down -v`；后者会永久删除该新版数据库卷。生产使用前必须完成备份/恢复演练。参见 [V1 部署、备份、恢复及验收](V1_OPERATIONS.md)。

## 费用报账与财务审批

- 费用报账支持草稿、提交、财务批准/退回、退回修改和全额付款登记。
- 每笔费用明细有发生日期、类别、说明与两位小数金额；后端使用 `DECIMAL(18,2)` 计算总额。
- 可选关联项目，支持上传私有附件；申请人仅可编辑自己的草稿，财务审批人员可查看待审单据。
- 审批人不得批准自己提交的报账；付款登记必须使用唯一流水号，且付款金额必须等于批准金额。
- 已付款报账不可再次付款或修改；状态流转、版本冲突和业务历史由后端验证。
- 当前实现为**全额付款登记**，尚不支持部分付款、银行对账、发票核销或总账记账。

## 发票与应收应付台账

- 财务人员登记应收（销项）或应付（进项）发票，可关联客户、合同、项目；关联关系由服务端验证。
- 发票从草稿经不同账号审核后进入未结状态，支持分次收付款核销，未结余额按 `DECIMAL(18,2)` 精确计算。
- 每笔核销必须提供全局唯一的流水号；禁止超额核销、重复核销、对作废或结清发票继续核销。
- 新版财务导航可查看应收/应付汇总、发票详情、核销明细及业务状态历史。
- 当前是内部业务发票登记与应收应付台账，不代表已经对接税务电子发票平台、银行接口或法定会计总账。

## V1 候选版完整业务范围

客户/合同/中间人/项目、维修与维护保养年度记录、公示卡及原件、消防检测现场出勤与问题清单、照片分类和审核、消防规范及条款、系统模板、公共 Word 模板、检测资料版本、DOCX 组合生成、独立审核签发、交付历史。旧数据仅通过隔离预检、离线归档和人工映射试迁移；财务深化、评定评估专用报告和小蜜蜂自动对接仍暂缓。

本地统一验收（Linux/WSL）：

```bash
bash scripts/erp-next-local-verify.sh --static
bash scripts/erp-next-local-verify.sh --full
```

第一条只检查 shell 语法及离线迁移单测；第二条执行 Maven、前端构建及独立临时 Compose API Smoke。两条不替代实际 Word 打印、浏览器操作及真实历史数据试迁移。详见 [V1 验收门槛](V1_ACCEPTANCE.md)、[检测报告说明](INSPECTION_PROFILE.md)、[迁移操作](LEGACY_MIGRATION.md)。GitHub Actions 仍只允许手动触发。尚未验收前不得视为生产就绪。

## 账户与交互规范

- 仅三个固定账户权限：普通员工、管理人员、超级账户；唯一超级账户用户名 admin，不能停用或降级。只有 admin 管理登录账号、绑定员工身份及迁移。管理人员负责业务管理、财务及审核签发（仍遵循独立审核与工程师资格规则）；普通员工进行日常项目/现场/报告编制/维保与本人报账，不得审核签发或管理账户。具体业务授权仍需用户实测确认。
- 不提供自定义角色、权限复选框、公开自主注册或通用操作审计。原有通用审计记录只作退役保留；照片审核、报告审核、签发、交付及财务状态历史不属于被删除的通用审计。
- 账户列表只展示姓名、账号、权限、状态及操作。新建弹窗四字段，编辑弹窗可重置密码、启停（admin 除外）。列表不展开表单；复杂操作使用复用 ModalDialog 并在后续改造中按步骤引导，提交前核对、错误在弹窗内展示、取消不写入。此次仅完成账户页，不宣称全部业务页已改造。
- 全新数据库直接初始化三种固定角色，由引导流程创建唯一 admin。最终完整版迁移旧 sys_user 时保留兼容 BCrypt 哈希及启用状态；旧 admin 不自动覆盖新版管理员。开发测试不升级中间版本。

## 基础资料、合同与项目

员工档案、中间人管理、甲方管理与消防规范资料库归入基础资料；合同管理和五类项目分别进入合同与项目。经营驾驶舱暂时移除。新增合同默认自动创建同名同类型项目，项目日期取自合同；可明确关联已有同甲方同类型项目，维保续签使用原项目。维保合同必须填写起止日期，其他服务的结束日期允许为空。
