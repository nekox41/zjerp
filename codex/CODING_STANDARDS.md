# 代码规范

- 使用Java17和现有包结构。控制器负责路由、角色权限、分页和审计；服务负责规则及事务；Mapper仅负责持久化。禁止从Spring代理对象直接读取注入字段，使用服务方法。
- SQL用参数绑定；动态表名只能来自服务器类型白名单。MySQL字段名避开保留字（计数器使用sequence_value）。不得让客户端指定存储表、创建者、正式编号等受控字段。
- 金额用BigDecimal/DECIMAL和字符串接口；展示四舍五入不等于修改历史数值。日期明确格式及Asia/Shanghai时区；未知状态存未知，不自动补造到场、报告或付款事实。
- 复合写入放在服务事务中。编号使用数据库锁和唯一约束，不用内存计数、MAX+1或前端申请。项目页更新必须携带版本号，子项必须带父项目条件。
- 重要变更记录@Log。异常返回可理解的业务消息，不将SQL和凭据直接暴露给用户。
- 新界面复用共享样式及业务组件，遵守前端DESIGN_SYSTEM.md。明确必填项、保存防重复点击、删除确认和未保存离开提示；异步搜索防止旧响应覆盖新结果。
- 密钥和密码只来自环境变量；不提交.env、SQL数据备份、上传文件、客户清单、临时令牌或运行状态文件。不要为了同步源码改写生产凭据。
- 验证覆盖真实边界：权限、错误输入、并发编号、版本冲突、跨项目操作、附件内容及迁移一致性。不要只写重复实现的测试。
- 生产只做独立只读验收；含增删改查的集成脚本必须先验证隔离实例标记。删除/恢复脚本有明确目标、前缀、状态及数据来源检查。
- 每次发布记录源码提交、冻结镜像ID、SQL版本、配套备份和验收结果。GitHub正常提交，不等待Actions；B不能访问Docker Hub，采用B本机构建，避免在4GB机器上并行重型构建。
