# 现场照片整理与报告插图工作流

本模块属于新版 ERP 的项目交付流程。它将照片批次、消防系统一级分类、DOCX 章节插图、报告版本及审核交付关联起来。

## 工作流程

1. 在项目详情中建立项目，并在「报告管理」创建项目报告草稿。项目可以暂未签约；合同可关联多个项目，一个项目也可以关联多个合同。
2. 打开项目的「照片整理」或侧边栏照片工作台，创建照片批次；批次可选关联一次现场服务记录。
3. 批量导入 JPG/PNG。浏览器先将照片缩放为最长边 1800px 的 JPEG 副本，再上传到服务端私有文件存储。原始本地照片不会被改写。
4. 以卡片/表格预览，人工确认每张照片所属消防系统一级分类。支持多选批量分类、筛选、放大预览、组内上移/下移和移除。
5. 选择报告及 DOCX 模板。模板可从报告当前版本附件中选取，也可以上传新模板并关联到报告。选择模板后，系统会先扫描该文件实际存在的系统照片锚点，分类下拉框只开放模板支持的系统；若照片分类不在当前模板内，会阻止预览/插入。
6. 生成预览 DOCX。系统根据模板中各系统标题和其下的「现场检测照片」标题定位照片表格，复制该表格的布局/单元格样式，并在对应系统最后一组照片后追加新的 2×2 照片组；每组最多四张，超出后继续追加照片组。
7. 使用 Word 检查预览文件的照片归属、分页、表格布局、图片完整性及签章区。确认后点击「确认插入」，系统将生成文件存入私有文件存储，并创建新的不可变报告版本。
8. 新报告版本自动保留上一版本附件、关联模板和生成后的 DOCX。报告仍处于草稿状态，可继续编制、提交审核、审核通过、签发、归档并登记邮寄/签收记录。

## 数据与安全

- 照片批次和分类状态持久化保存，页面刷新后不会丢失。
- 一个批次最多 300 张照片，合计不超过 120 MB；单张上传文件不超过 25 MB。
- 仅允许 JPG/PNG；图片像素上限 4000 万。上传后照片和生成文件均存储在服务端私有文件目录。
- 照片批次一旦插入报告即锁定，避免同一批次被重复修改或再次插入。
- 报告插入要求报告处于草稿或退回状态、版本号匹配、所有照片完成分类，且批次项目与报告项目一致。
- 生成 DOCX 不会覆盖原始模板、原始照片或旧报告版本；插入结果通过报告版本和附件记录追溯。
- API 分别校验 `photo:read`、`photo:write`、`report:read`、`report:write` 权限。文件下载仍经过私有文件权限校验。
- 项目负责人和技术负责人必须为不同的在职工程师，并且在新增/调整负责人时必须有有效资格记录。员工关联登录账号后，系统按员工类型同步基础角色：工程师、操作员、普通员工、管理人员。

## DOCX 定位规则与限制

- 已重新检查两份真实报告样本：两份文件都以正文段落作为系统标题，随后是检测明细表，再出现一个或多个「现场检测照片」段落、2×2 照片表格和「注：应附彩色照片并注明日期，日期应如实填写。」说明段落。
- 系统通过 DOCX 正文段落识别消防系统标题，再在该系统标题之后寻找最后一个「现场检测照片」标题及其照片表格；多组照片时只追加到该系统最后一组之后，不会插入到系统检测明细表之前。
- 支持章节序号（如「十、消防专用电话系统」「十二、消防供配电设施」）以及常见系统名称别名，例如「应急照明和疏散指示系统」映射到「消防应急照明和疏散指示系统」，「消防供电设施」映射到「消防供配电设施」。
- 如果所选模板没有对应系统的照片锚点，系统会拒绝生成，不会擅自将照片放到文末或其他系统。
- 插入采用“追加照片组”，不删除或替换原报告已有照片。照片按用户保存的顺序分组，最多四张一组。
- 自动化测试使用合成 DOCX 验证插入位置、原内容保留、图片数量及别名；端到端 Smoke Test 验证上传、分类、预览、插入、版本生成、审核签发和邮寄状态。
- 真实检测报告仍须在 Word 中人工验收：不同报告模板可能存在标题文字差异、合并单元格、浮动图片、分节符和页眉页脚等结构。未通过真实样本逐一验证的模板应停止插入并补充定位规则。
- 当前不做 OCR/AI 自动分类，不判断照片是否符合检测结论，不自动填写照片拍摄日期，也不生成签章。

## 其他项目模块

- 客户与联系人：客户档案、多个联系人、主要联系人、关联合同。
- 中间人：独立合作方档案及其合同列表。
- 合同：直接签约/中间人签约、分成比例、合同附件、公示卡、变更记录；合同启用前必须至少关联一个项目。
- 项目：可在未签约时创建；合同关联为多对多，支持初始、续签、补充关系及当前合同。
- 员工：工程师、操作员、普通员工、管理人员；工程师资格记录与有效期。
- 项目交付：检测范围单体/车库分期/共用设施、维护保养状态、维保现场记录、技术服务记录、问题整改状态历史。
- 报告：项目直接归属报告、版本历史、附件、编制/审核/签发/归档和邮寄交付。

## CI 与人工验收

GitHub Actions 的 ERP Next Schema and Smoke Test 会执行 V1–V9 迁移和全流程 Smoke Test。合并前需确认 Monorepo Build、Docker 构建及 Smoke Test 全部通过。真实 Word 样本的版式和打印效果仍需人工验收。
