# 现场照片整理工作台（第一轮）

关联总控需求：[#8](https://github.com/nekox41/zjerp/issues/8)

## 第一轮已实现的范围

1. 登录新版 ERP（`/next.html`），有 `report:write` 权限的账号可使用「现场照片整理」。
2. 一次批量导入最多 300 张 JPG/PNG，浏览器端直接生成缩略图，支持卡片/表格切换。
3. 单张设置消防系统，或多选照片后按系统批量分类；按分类筛选和查看未分类照片。
4. 上传一份现有的 `.docx` 报告（不修改源文件），点击「生成 DOCX」。
5. 前端压缩导出用照片副本，服务端使用 Apache POI 将一级系统分类的照片以两列版式**追加至报告末尾**，导出新的 DOCX。
6. API 要求已认证且具有 `report:write` 权限。未分类照片不能提交；只接受有效分类名、JPG/PNG 和 DOCX。
7. 服务端不保存批量上传的报告或照片；浏览器页面刷新后分类状态会丢失。业务原件应由工作人员自行保管。

## 数据与验证约束

- 第一轮只按消防系统一级分类，不识别具体设施、不强制水印/OCR，也不推断检验结果。
- 本功能**不修改历史批准/签发的报告记录**，不生成签章，也不自动更改任何检测结论。
- 当前只是在 DOCX **末尾增加分类照片页**。尚未将照片插入原报告中各系统检测记录后的精确位置。使用者须核对分页、表格和照片完整性。
- 前端支持单批最多 300 张；每张导出用图片将缩放为最大边 1500 像素的 JPEG。原始照片只用于本地预览，不上传原件。
- 报告模板最大 25MB，导出照片每张最大 8MB、照片总量最大 220MB，整个 multipart 请求最大 250MB。
- 如果需要将照片准确插入现有报告各一级系统原有的照片表格位置，下一轮需要先解析两份真实 DOCX 的锚点规律，并为文档中的系统设置可靠定位规则，再做模板差异测试。
- 生产环境仍需要执行人工 Word 打开检查、针对真实报告的合并/分页检查、权限/恶意输入/大批量性能测试。此功能不应视为已经正式验收。

## 验收步骤

1. 管理员使用 `/next.html` 登录，打开「现场照片整理」。
2. 导入三张照片，单张和批量各设置一级系统分类；切换卡片/表格和筛选，分类保持一致。
3. 保留一张未分类照片，验证生成前提示并定位未分类筛选。
4. 完成全部分类，上传现有 DOCX，点击生成。
5. 下载后用 Word 打开，确认原正文仍在，末尾按系统分组出现对应照片且照片没有重复或遗漏。
6. 不具 `report:write` 的账号直接调用 `POST /next-api/report-photos/docx` 应被拒绝。
