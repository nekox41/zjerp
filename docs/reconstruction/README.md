# ERP 重建工程

> 状态：设计基线 v0.1（2026-11-21）。这是新架构的工作基线，不是已完成的系统设计，也不代表任何生产数据已迁移。

本工程以业务合理性为第一原则，不要求新系统沿用旧系统的菜单、代码分层、API、数据库表或操作流程。旧系统只作为**业务事实、历史记录与数据来源**。新系统应在独立目标模型上设计，最后通过专用迁移程序导入旧数据。

## 决策状态

| 决策 | 当前结论 |
|---|---|
| 是否必须兼容旧代码/菜单/API | 否 |
| 是否必须沿用旧数据库结构 | 否 |
| 是否保留旧业务事实与历史价值 | 是 |
| 是否允许自动猜测不确定的业务关联 | 否 |
| 新旧系统是否直接共用生产数据库 | 否，目标是独立目标库 |
| 是否要求用户手工逐条迁移 | 否，目标是迁移向导批量自动迁移 |
| 是否允许迁移过程覆盖/删除源数据 | 否 |
| 是否在未完成核对前切换生产 | 否 |

## 当前阶段

先完成可证实的现状审计与目标模型设计，再实现目标系统核心业务骨架和迁移工具。未经过业务确认的规则必须标记为待确认，不能伪装成已确定需求。
