# 旧 ERP 数据一键迁移设计

> 版本：v0.1；状态：方案。当前没有实现迁移程序，也没有连接生产数据库。本文定义目标行为与安全边界。

## 1. 目标体验

管理员在新系统部署完成后，进入“系统迁移”向导：

1. 连接旧数据库与旧文件存储（只读凭据）。
2. 自动扫描源表、字段、行数、主键、外键/逻辑引用、文件引用和数据质量。
3. 展示自动识别出的旧版本、数据规模、可迁移对象、异常和预计耗时。
4. 生成映射方案；高置信度规则自动映射，存在歧义的数据要求确认。
5. 点击“预演迁移”执行全量 dry-run，不写目标业务数据。
6. 展示可迁移数量、待确认数量、冲突、缺失文件、金额/数量校验结果。
7. 管理员确认后点击“一键正式迁移”。
8. 实时展示阶段进度、失败原因和可重试阶段。
9. 完成后生成迁移报告，展示源/目标行数、金额合计、附件 hash、关系完整率和待处理清单。
10. 验收通过后执行业务冻结/最终增量同步/切换；旧系统保持只读归档。

“一键”是指自动化批量执行，不意味着跳过预演、确认或数据校验。若存在未解决的关键财务/身份歧义，系统必须阻止切换，而不是悄悄猜测。

## 2. 迁移拓扑

- 旧系统数据库：只读访问，禁止写入。
- 旧文件存储：只读扫描与复制，不修改源文件。
- 新系统目标数据库：独立 schema/实例，使用全新目标模型。
- 新文件存储：独立目标目录/对象存储。
- 迁移控制库/作业记录：记录源快照指纹、迁移批次、步骤、映射、错误、重试和校验结果。
- 迁移执行器：独立于日常业务服务；可在部署环境内运行，凭据从密钥配置读取，不能提交到 Git 或日志。

禁止在旧库上原地重建表或用目标 schema 覆盖旧表。

## 3. 迁移阶段

### A. Source discovery
- 自动读取 schema、列类型、主键、索引、表行数和时间范围。
- 检查旧数据版本、兼容表、历史表、视图和已废弃入口。
- 建立数据字典和源数据快照标识。
- 不输出个人敏感字段到普通日志；报告支持脱敏。

### B. Mapping
- 每一类源对象对应明确 mapping 规则和版本。
- 优先用旧主键/明确外键/历史迁移映射表关联。
- 名称、电话、编号相似度只能用于提示人工核对，不能自动合并员工、客户、合同或项目。
- 不能唯一匹配的关系进入 exception queue，原始引用和值完整保留。
- 金额精度、空值、时区、日期、状态码、附件列表逐项定义转换规则。

### C. Dry-run
- 目标库结构与索引可创建在隔离目标 schema；不写入正式业务数据。
- 计算每张表的源行数、目标预计行数、跳过/冲突/待确认数量。
- 预估附件数量、总字节数、缺失文件、重复内容和 hash。
- 运行关系约束检查、金额合计、状态映射覆盖率和抽样报告渲染检查。
- 输出完整 dry-run manifest，可重复执行并对比不同规则版本。

### D. Import
- 为每个源记录建立稳定映射：`(source_system, source_table, source_pk) -> target_entity, target_id`。
- 保留旧主键、原始字段快照、原状态/文本和来源时间。
- 目标 ID 可重新分配；旧 ID 通过 legacy mapping 查找，不强迫新业务主键沿用旧 ID。
- 分批事务导入；每批可重试，唯一键与迁移批次避免重复。
- 文件复制采用内容 hash 校验，保留原始文件名、扩展名、来源路径、业务引用；重复二进制可以去重但保留多个业务引用。
- 对未知字段不静默丢弃：写入受控 legacy payload 或异常队列，设定保留策略。

### E. Reconciliation
- 比较源/目标记录数量、关键字段、金额精确合计、附件数量/字节数/hash。
- 核验所有目标关系的引用完整性和待确认清单。
- 对财务按账户、期间、方向、状态、合同、项目分别对账。
- 对报告抽样比对 PDF/附件和快照；对合同/项目抽样检查关联。
- 生成可签字验收的机器报告与人工抽样记录。

### F. Cutover / rollback
- 正式切换前冻结旧系统写入，执行最终增量导入（若支持增量）并再次核验。
- 目标系统开始写入后，旧系统保持只读，不进行双向同步。
- 切换失败时恢复旧系统服务；目标系统隔离保留供排查，不回写或覆盖源库。
- 切换后的新数据不应通过“回滚旧库”丢失；必须制定新系统切换后的备份与恢复点策略。

## 4. 必须保留的数据

- 合同、合同金额精度、日期、归属原文、付款约定、附件及变更历史。
- 项目、项目编号、历史编号、项目分类待确认标记、合同引用及历史快照。
- 员工、旧系统账号映射、资质证书、人员资料和历史姓名快照。
- 报告内容、生成文件、模板/签字/人员/资质快照、报告编号和版本。
- 问题、计划、现场登记和项目文件。
- 维保卡、编号占用历史、成品资料和项目关联。
- 报账申请、报账人/录入人区分、原始状态、凭证及支付关系。
- 资金账户期初余额、流水、内部转账成对关系、作废原因与操作审计。
- 发票号码、金额、税额、购方信息、附件、作废状态和历史关系。
- 统一文件元数据、源 URL/路径、原始二进制（若存在）及缺失标记。
- 原始数据快照、来源表/主键、迁移批次和映射关系。

## 5. 不得自动猜测的情况

- 重名员工或联系人合并。
- 相同合同名称/编号但不同类型或来源的记录合并。
- 项目与合同缺失关联时仅凭名称匹配。
- 历史费用分摊到多个项目。
- 账面汇总与明细不一致时自动调整金额。
- 以缺失附件的 URL 假装文件存在。
- 用空值填充为 0、用未知状态强制映射为“已完成”。
- 将历史“已支付”状态当作存在真实账户流水。
- 将旧系统账号自动提升为新系统角色或管理员。

## 6. 幂等、审计与安全

- 每次迁移有唯一 batch ID、源快照 fingerprint、mapping version、目标版本。
- 每条导入记录有 source key 和目标映射唯一约束。
- 作业步骤有状态、尝试次数、输入/输出计数、错误和 checkpoint。
- 重跑同一批次不重复创建记录；规则版本变化时先生成新的 dry-run。
- 源凭据只读、目标凭据最小权限；秘密不进代码仓库、迁移报告或日志。
- 迁移报告默认脱敏；敏感附件和个人资料仅在授权范围内复制。
- 迁移执行前后自动生成源/目标备份或快照；备份恢复演练是上线门禁。

## 7. 验收门槛

- 源库零写入、零删除。
- 所有源表都有“已迁移/有意排除/待确认/失败”的去向，不允许静默漏表。
- 财务关键金额精确到分且按口径对平；差异必须解释，不得自动抹平。
- 所有已存在文件的 hash 一致；历史缺失文件明确保留缺失标记。
- 所有高风险关联均可追溯；歧义项有明确责任人和处理状态。
- 迁移脚本可在相同源快照和规则版本下重复运行且结果一致。
- 在隔离环境完成完整演练后，才能用于生产切换。

## 8. 逐步实现顺序

1. 只读 Source Inspector：表/字段/行数/引用/文件扫描。
2. Mapping Registry：显式可版本化的映射规则。
3. Dry-run Planner：数量、金额、引用和附件差异报告。
4. Import Runner：分批、可恢复、幂等迁移。
5. Reconciliation：自动对账与人工验收。
6. Admin Wizard：将上述流程封装为用户可执行的一键体验。
7. Final Sync & Cutover：冻结、增量、切换和回滚。
