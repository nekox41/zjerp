# 第一版可用 ERP 产品范围与交付路线

> v0.1 / 2026-11-22。本文将重建工作的主目标从“继续完善迁移工具”校正为“交付第一版完整可用的 ERP”。迁移是上线门禁和数据保障能力，不是主产品。

## 1. 产品目标

交付一个可部署、可登录、可按角色使用的模块化单体 ERP。普通员工能够围绕合同、项目、人员、服务报告、文件和财务完成日常工作；管理员能够维护权限、配置和系统运行；业务对象之间的来源、关联、状态与下一步清晰可见。

不要求复制旧菜单、旧表或旧代码。必须保留旧业务事实和历史价值，并确保历史数据有明确去向。

## 2. 第一版业务范围

| 优先级 | 领域 | 首版必须具备 |
|---|---|---|
| P0 | 平台基础 | 登录、用户/角色/权限、组织数据范围、审计、文件服务、编号/字典/配置、schema 版本、部署/健康检查/备份恢复 |
| P1 | 客户与合同 | 客户/联系人、合同 CRUD、合同状态/变更/附件、合同关联项目 |
| P1 | 项目交付 | 项目 CRUD、合同来源、成员、现场记录、问题整改、工作计划、文件和项目工作台 |
| P1 | 人员与资质 | 员工档案、业务角色、资质与有效期；与登录账号分离 |
| P1 | 技术服务与报告 | 服务工作包/过程记录、报告草稿/预览/审核/签发、版本快照和归档 |
| P1 | 工作台 | 我的待办、待补资料、最近访问、逾期提醒、跨模块上下文 |
| P2 | 财务 | 报账/审核/退回、真实付款、账户/流水/转账、发票登记和项目/合同摘要 |
| P2 | 维保 | 维保项目、成品资料、维保卡生成、编号和归档 |
| 上线门禁 | 历史数据迁移 | 完整去向、全量隔离演练、数量/金额/关系/文件 hash 对账、备份恢复演练、内置管理员向导 |

财务第一版必须准确区分报账批准、实际付款、发票开具、客户到账和核销；未确认的复杂分摊/核销场景不虚构。

## 3. 关键用户旅程

1. 管理员创建用户、角色和组织范围；普通员工登录并只能访问授权数据。
2. 建立客户/委托单位与合同，从合同上下文创建项目。
3. 项目管理成员、现场记录、问题、计划、文件和状态。
4. 从项目创建服务工作包，完成过程记录，生成报告草稿、预览、审核和正式签发；签发内容保留人员/资质/模板快照。
5. 员工提交费用申请，财务审核并登记实际付款，形成账户流水；不把审批伪装为付款。
6. 登记发票和实际到账，状态分离并可追溯。
7. 用户从工作台或项目工作空间理解待办、缺项、关联对象和下一步。
8. 管理员在新版 ERP 内完成历史数据迁移；无法安全转换的历史对象保留为可检索档案/原始快照，所有记录有来源追踪。

## 4. 架构交付原则

- 模块化单体；模块有明确数据所有权和应用服务边界。
- 前后端、数据库、权限和部署作为一个纵向切片交付。
- 每个关键状态转换在后端校验并写审计记录。
- 金额使用定点十进制；文件使用私有存储和业务引用；历史报告/签发快照不可被当前主档修改。
- 数据库 schema 变更版本化；区分空库初始化与已有库升级。
- 关键业务测试包含权限、事务、并发、幂等和跨域状态。

## 5. 迁移的正确定位

迁移必须保证历史数据完整、有迹可循，但不要求把所有旧记录强制转换成新版可编辑实体。

每条来源数据最终必须落入以下之一：
- 已转换为新版业务对象；
- 作为历史档案/原始快照保留；
- 因缺少原件或关联歧义进入待确认队列；
- 经明确规则有意排除并记录原因。

迁移工具已有只读 inspector 和私有 SQL 暂存基础。目标模型尚未冻结时暂停扩大扫描/映射 UI 的工作；先交付真实 ERP 业务模块。正式上线前再完成完整内置迁移向导、隔离全量演练、对账与恢复验证。

## 6. 实施顺序

1. 冻结首版范围、术语和关键状态机；只处理阻塞实现的业务决策。
2. 平台基础：模块边界、目标 schema、身份权限、审计、文件、部署与数据库升级。
3. 客户/合同纵向切片。
4. 项目工作台纵向切片。
5. 人员/资质与服务/报告纵向切片。
6. 工作台/待办与文档体验。
7. 财务闭环。
8. 维保与首版剩余必需能力。
9. 迁移完整化、全量演练和上线验收。

## 7. 完成定义

功能只有同时满足以下条件才算完成：
- 有真实数据库持久化、后端业务规则/API、权限和前端操作；
- 有加载/空/失败/冲突/未保存等交互状态；
- 有单元/集成测试及真实角色 E2E；
- 桌面与 390px 手机端完成关键任务；
- 数据库升级、备份恢复、部署链路通过隔离环境验证；
- 关键数据可追溯，金额与状态口径正确；
- 文档说明配置、操作、限制和回滚方式。

CI 通过或页面可打开都不等于业务功能完成。
