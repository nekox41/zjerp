## 7. 对目标架构与迁移方案的直接影响

1. **以旧主键建立永久来源映射**：尤其报告编号有重复，项目编号存在别名，不能用业务编号做唯一迁移键。
2. **新系统支持未完成主数据**：项目 297 条待编号、3 条待分类、523 条无合同；员工 16 条类型待确认。迁移不能因为新系统必填字段更严格就丢弃这些记录。
3. **合同类型扩展保留语义**：五类合同字段结构虽高度相似，但需要逐字段比对后再决定目标类型模型。
4. **项目与历史报告来源分层**：项目主记录、旧项目编号来源、报告归档记录和报告附件引用应分别迁移，保留匹配依据。
5. **文件对象与引用分离**：同一 URL 在报告/项目档案间重复，不应重复存储二进制；原件迁移另行扫描验证。
6. **财务不造账**：账户、流水、发票当前为空；保留报账和历史费用，但不得推断已付款或账户余额。
7. **历史审计日志分类保留**：登录/操作日志属于安全审计数据，不应混入业务实体；制定独立保留期、脱敏和访问策略。
8. **源库只读，目标库独立**：本次快照可作为第一份迁移演练输入；正式生产迁移仍需在切换前冻结写入并获取最终增量快照。
